Low-Rank Shared Core in Huginn-0125

Phase 9 · branch lowrank-shared · pretrained 3.5B loop LM · RTX 5090 · 2026-10-12 · follows Phase 8 (toy model)

We applied the W ≈ UV low-rank parameterization to the recurrent core of the pretrained 3.5B Huginn-0125 (1.58B core weights). Raw SVD compression alone incurs a substantial penalty (loss rises from 2.454 to 3.063 at rank 2048, 2× core compression). However, fine-tuning only the low-rank U and V factors recovers nearly half of the lost quality, with speedups and recovery transferring across recurrence depths.

  • Huginn's core weights are not naturally low-rank: At rank 2048 (2× core compression), MLP projections retain only 72–73% of singular energy; attention projections retain 85–90%.
  • Error settles into a stable state: Relative hidden-state error rises over 8 loops (0.47 → 0.79 at r=2048) and flattens at 0.80 through loop 64.
  • Recovery fine-tuning succeeds: A 1,000-update continuation run closed 47.4% of the compression penalty at 32 loops on the 256-sequence validation set (2.8272 vs 3.1128 raw SVD; full is 2.5107).
  • Recovery generalizes across loop counts: Although trained strictly at 32 recurrences, recovery benefits transfer evenly across 4, 8, 16, 32, and 64 loops (46.8%–50.7% penalty recovered).
  • Verified forward speedup: Measured full-model latency is 1.57× faster at 16 loops (201.0 ms vs 315.6 ms) and 1.60× faster at 32 loops (381.0 ms vs 610.8 ms).
  • Plateau around 16 loops: Both full and recovered models achieve almost all recurrence gains by 16 loops (gaining <0.003 loss from 16 to 32 loops), highlighting 16 loops as an effective inference operating point.

3. Recovery Fine-Tuning: Closing the Gap

To repair the compression error, we fine-tune only the U and V factors of the core projections (0.79B parameters at rank 2048), keeping all remaining model components (embeddings, prelude, loop adapter, coda, LM head) completely frozen. Training uses truncated backpropagation through the last 8 of 32 loops with AdamW (lr 1e-5, linear warmup).

Verified Batch Configuration & Token Accounting:
• Microbatch: 1 sequence (1,024 target tokens).
• Gradient Accumulation: 8 steps → Effective batch: 8 sequences = 8,192 tokens per optimizer update.
• Pilot run (Updates 1–225): 225 updates × 8,192 tokens = 1.84M token presentations.
• 1,000-Update Continuation (Updates 226–1225): 1,000 updates × 8,192 tokens = 8.192M additional token presentations (drawn from an allocated buffer of 20,000 sequences, indices 0..7,999).
• Data Reuse: Because the continuation run initialized its data iterator at index 0 of shard 0, sequences 0..1,799 were repeated presentations from the pilot; sequences 1,800..7,999 (6.35M tokens) were fresh presentations.
• Cumulative Token Presentations: 1.84M + 8.19M = 10.03M token presentations.

5. Key Findings

  • Recovery transfers across recurrence counts: Although recovery fine-tuning was trained strictly on 32 loops, recovery gains transfer across 4, 8, 16, 32, and 64 loops (~47–51% penalty recovered). The factors learned to improve recurrent state representation generally, not overfit a specific step count.
  • The 1,000-update continuation broke through the initial plateau: Extending training by 1,000 updates pushed validation loss down from 2.8669 to 2.8272 on the 256-sequence set, closing an additional 6.6% of the compression penalty.
  • 16 loops represents an efficient operating point: Both the full model and recovered models plateau near 16 loops (Full gains only 0.0033 from 16 to 32 loops; Recovered-1225 gains only 0.0029). At 16 loops, the compressed core delivers 201.0 ms latency (1.57× speedup) at a validation loss of 2.8301.
  • Remaining quality gap: Even with 47.4% of the compression penalty recovered, a gap of ~0.316 loss remains vs the full model (2.8272 vs 2.5107 at 32 loops). Uncompressed weights possess representational capacity that rank-2048 alone cannot fully match without architectural changes (such as non-uniform rank allocation).

6. Caveats

  • Experimentation set used for validation: All recovery metrics reported here use the 32-sequence and 256-sequence validation samples. A separate, untouched held-out sample must be reserved for final evaluation.
  • Uniform projection rank: Every projection in the core currently uses an identical rank $r=2048$. Spectrum analysis indicates that MLP projections lose significantly more singular energy than attention projections, suggesting that non-uniform rank allocation could yield higher quality at the same parameter budget.
  • Frozen adapter: The recurrent state adapter remains full rank (10,560 × 5,280).
  • Eager PyTorch execution: Latencies measure eager execution without torch.compile, CUDA graphs, or custom fused U·V kernels.

7. Next Steps

  • Evaluate non-uniform rank allocation: allocate higher rank to MLP projections (where energy loss is greatest) and lower rank to attention projections at an identical total parameter budget.
  • Benchmark downstream task performance (e.g., GSM8K reasoning benchmarks where recurrent refinement is most prominent).
  • Test higher ranks (such as $r=3072$) under recovery fine-tuning to evaluate quality retention vs latency.
  • Evaluate on an untouched held-out test split for final independent reporting.
